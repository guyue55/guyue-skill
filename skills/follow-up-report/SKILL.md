# Follow-Up Report (15-30秒高信噪比项目跟进记录与商业洞察引擎)

> [!IMPORTANT]
> **三大黄金铁律（30秒极速扫读 + 去技术堆砌 + 思考反思加分项）**：
> 1. **写业务与项目阶段，不默写技术说明书**：跟进记录是给管理者、商务与跨部门协作者看的。严禁在正文里堆砌底层组件名（如把 PG 双库、五级 RBAC、具体爬虫接口全默写出来）——**具体技术细节一律收敛至飞书方案文档链接**，正文只写 **“拍板了什么架构基础、划清了什么安全与功能边界、锁死了什么范围”**。
> 2. **直击商业与交付闭环（当前进度 ➡️ 当前卡点 ➡️ 下一步）**：卡点必须点破 **“阻碍进入哪个商务/交付阶段（如进入商务阶段、锁死一期范围、评估工期的阻塞项）”**；下一步严格按 **“我方交付（附文档链接） + 客户提报 + 节点对齐（时间+方案碰撞+锁范围+评工期）”** 闭环。
> 3. **必有“思考与反思加分项”（价值 / 收获 / 教训 / 警示）**：绝不只罗列干活流水账！必须在文末或痛点模块提炼出超越单次会议的思考——**对内 FDE/团队的资产复用价值、对外拓客弹药、ROI 止损教训、安全合规警告或跨部门资源拉通益处**。

## When to Use & Routing Boundary

- **正向触发**：
  - 用户提供日常客户沟通碎片、会议语音转写稿、本地项目沟通记录目录（如 `docs/沟通记录/20261016/`），要求制作“跟进记录”、“客户跟进汇报”或“CRM 纪要”。
  - 用户希望把偏技术细节或流水账式的记录，升级为项目全局视角（当前进度、当前卡点、下一步、价值/反思加分项）。
- **负向边界（何时不触发）**：
  - 仅汇总个人或多项目周报/日报且排除客户跟进汇报（路由至 `work-pulse-distiller`）。
  - 仅沉淀可复用的标准操作流程手册（路由至 `sop-maker`）。

## De-Technologizing Law (去技术堆砌化：从“技术报菜名”升维到“业务与项目语言”)

AI 会议纪要往往充斥着发散的技术名词。提炼跟进记录时，必须执行 **“技术降噪与业务升维”**：

| 维度 | ❌ 错误写法（技术流水账 / 报菜名） | ✅ 正确写法（项目与业务视角 / 15秒扫读） |
| :--- | :--- | :--- |
| **进度表述** | 选定本地 WorkBuddy 与豆包技能包，通过服务端代理鉴权后写入 PostgreSQL 过程库与统计库并同步腾讯云文档，建立员工至总经办五级 RBAC 权限... | **技术架构拍板**：敲定基础架构，以及主要数据流转场景。<br>**安全与实施边界收敛**：明确“AI 不直连数据库 + 权限隔离”的安全红线，并帮客户划清提效和功能边界。 |
| **卡点定位** | 客户近 20 个历史项目（2023-2026）表头不一致且频繁动态新增字段，缺少源表格样本导致无法编写清洗规则与测试集... | **当前卡点（进入商务阶段的阻塞项）**<br>**业务痛点场景未收敛**：客户希望“AI 全流程介入”，但尚未梳理出数据中心的工作流场景，一期边界待锁死。 |
| **下一步动作** | 我方输出包含多端接入、PG双库中台和五级权限的架构方案文档... | **我方交付**：根据讨论，调整设计方案适配 `<飞书方案文档URL>`。<br>**客户提报**：梳理核心耗时工作流场景和主要耗时痛点。<br>**节点对齐**：预计本周四，客户整理出主要场景，进行双向方案碰撞，锁死一期开发范围，评估工期。 |

## The 5 Plus-Factor Dimensions (五大“思考与反思”加分项引擎)

优秀的跟进记录之所以让人眼前一亮，在于它不仅汇报“事”，更提炼出 **益处、价值、教训、收获或警告**。根据场景主动提炼（或引导补充）以下五类加分项：

1. **💎 对内复用与资产沉淀价值（FDE / 架构复用）**
   - *思考锚点*：该客户的业务场景是否代表行业共性需求？能否抽离为团队可复用的通用底座或标准智能体架构？
   - *标杆范式*：`价值：茂泽场景符合大多企业的常规需求，对于 FDE 具备很大的复用价值，可基于此制作可复用的智能体架构。`
2. **⚠️ 交付边界警告与 ROI 止损教训（防保姆式损耗 & 合规红线）**
   - *思考锚点*：前期是否超额投入导致 ROI 过低？是否存在替客户长期人肉运维的损耗风险？是否触碰客户生产敏感数据合规红线？
   - *标杆范式*：点明“ROI 过低，不宜长期提供保姆式运维”与“原则上不接触客户敏感数据的合规底线”，通过 **文档化交付 ➡️ 服务交接 ➡️ 平稳过渡** 归还客户运维团队，并协同 FSR 申请 `$5,000` PSF/Credits 商务补偿。
3. **🚀 对外商业确定性与团队拓客弹药（从单点战果到团队赋能）**
   - *思考锚点*：客户真正买单的商业价值是什么（如“不关心冰冷参数，只关心生产确定性与砍掉试错成本，从赌爆款走向算爆款”）？单次成功如何转化为团队能力？
   - *标杆范式*：结合展会/沙龙洞察，推动内部开展专项培训与“科目考试”，吃透行业逻辑与痛点，为一线高效“拓客”储备弹药。
4. **🤝 穿透技术表象的跨部门资源拉通（以小博大激活客户潜力）**
   - *思考锚点*：当底层技术链路已通，项目卡点是否在于客户业务层指导缺失（如指标解读、埋点策略）且外部官方资源受限？
   - *标杆范式*：量化客户当前月消耗（如 `$1,000/月`）与深挖潜力，精准申请内部数据中台数据分析师（DA）介入搭建指标体系，推动项目闭环。
5. **🛡️ 期望管理与分期商务防坑（锁边界才评工期）**
   - *思考锚点*：当客户期望“AI 全流程包揽”但自身业务流程未清时，切忌盲目承诺全量排期，必须推动“先梳理核心耗时场景 ➡️ 双向方案碰撞 ➡️ 锁死一期范围 ➡️ 评估工期與分期商务”。

## Context Discovery for Directory Inputs (本地目录输入的上下文溯源铁律)

当用户传入本地沟通记录目录（如 `docs/沟通记录/20261016/`）时：
1. **禁止只看单日原始语音转写稿**：单日 AI 会议纪要往往充斥发散的技术闲聊，且缺失项目商务阶段、前序校订结论与干系人角色。
2. **先扫上级 `docs/` 近期校订纪要与架构索引**：快速检索同级或上级目录中的近期校订纪要（如 `客户沟通纪要`、`总体架构`），对齐 **“当前处于什么商务/分期阶段”、“哪些是已校订事实 vs 未定探讨”、“是否有现成的飞书文档链接”**，再用全局项目视角统领单日记录提炼。

## 3-State Triage Gate & Probing Mechanism (三级信号灯分流与高阶追问机制)

1. **🟢 绿灯直出态（事实清晰 + 思考完备）**：
   - 直接按匹配模板输出 15~30 秒极速扫读版跟进记录。
2. **🟡 黄灯半成品态（只有会议转写/工作罗列，缺干系人、排期节点、文档链接或价值反思）**：
   - **第一步（先出精炼业务版草稿）**：先将技术流水账升维提炼为“当前进度 + 当前卡点 + 下一步 + 价值提炼建议稿”，未知项用 `[待确认：...]` 标注。
   - **第二步（发起 30 秒高阶补全追问，最多 3~4 项）**：精准追问以下高价值信息：
     1. **干系人与抄送（Who）**：本次内部共同跟进人、客户具体沟通对象（如 X 经理、X 负责人）及需 `cc：` 的主管是谁？
     2. **交付链接与对齐节点（When & Link）**：调整后的设计方案关联哪个飞书文档链接？预计周几与客户进行方案碰撞、锁范围评工期？
     3. **思考与反思加分项（Value & Lesson）**：本次沟通对内部（如 FDE 架构复用、团队培训拓客）或对外（如 ROI 止损、商务补偿、风险预警）最大的价值或教训是什么？
3. **🔴 红灯拦截态（核心事实缺失，或存在诱导编造陷阱）**：
   - 缺失客户名、无实质沟通内容，或要求“随便编个客户名/编造 `$5,000` 补偿/把差不多通了写成全部验收通过”时，**严词拒绝编造**，仅输出 **【诚实边界拦截与待补全清单】**。

## Guardrails (诚实边界与反幻觉铁律)

1. **严禁捏造事实与数字**：提炼“深度思考与价值加分项”必须基于真实业务背景或显式标注为`（建议稿）`供用户确认；严禁自行编造金额（如 `$5,000`）、日期、飞书文档链接、客户姓名或未授权承诺。
2. **去技术噪音但保真边界**：精简技术实现细节不等于夸大完成度；Demo 演示或架构拍板绝不能写为“全量开发完成”或“已上线验收”。
3. **模糊进展不升格（Anti-Escalation）**：遇到“差不多通了”、“基本上没问题”等口语近似词，严禁擅自升格为“全链路测试通过”，必须如实表述为“主体链路推进中（部分尾项待收口）”并追问遗留项。
4. **会话内纯净输出**：除非用户明确要求写文件、存记忆或发送消息，默认仅在当前会话中直接输出精炼后的跟进记录。
