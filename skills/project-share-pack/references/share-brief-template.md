# Shared Story Brief

Use this as a working note before writing the document or PPT. Keep it in `tmp/`
unless the project needs a durable review record.

```markdown
# <Project Or Requirement Name>

## One-Sentence Purpose
<What it helps people accomplish and why that matters>

## Problem
- Current difficulty:
- Cost or impact:
- Why the current approach is insufficient:

## Main Flow
1. <Input or starting point>
2. <Main processing or decision>
3. <Result>
4. <Follow-up action>

## Capability Map
| Capability | Reader value | Current proof | Boundary |
| --- | --- | --- | --- |
| | | | |

## Proof Set
| Screen | What it proves | Source state | Privacy check |
| --- | --- | --- | --- |
| Entry/home | | runtime / sanitized demo / target experience | pass / pending |
| Result overview | | | |
| Report detail | | | |
| Delivery/action result | | | |

## Current State
- Confirmed:
- Not yet proven:
- Production checks still needed:

## Shared Wording
- Project name:
- Purpose:
- Workflow names:
- Report/output names:
- Status wording:
- Boundary wording:
```

The brief is a consistency tool, not another deliverable. Delete repeated prose
and keep each field to the minimum needed to prevent the document and deck from
drifting apart.
