# 工作脉搏蒸馏器 (Work Pulse Distiller)

> [!NOTE]
> 这是 `guyue` 能力体系中的**工作脉搏与工程周报智能蒸馏中枢**。
> 专门解决研发团队日常中“日报零散多源、项目交织交替、试错细节冗长、管理层缺乏直观进度大盘”的痛点，提供**结构化工程周报**与**红绿灯管理层大盘**的双层标准交付。

---

## 核心职责 (Core Job)

将多日、多项目、零散且带有大量过程性试错的日常碎片日志（日报、进展群聊、会议纪要、排障记录、上线链接等），经过**实体对齐、脱水去噪、维度聚合与价值重组**，提炼为统一标准的两层交付物：

1. **第一层：📊 结构化工程周报 (Detailed Project Weekly Digest)**
   - **多维结构化**：按项目归集并分类细化（架构与部署、功能与模块、UI/UX 与交互、性能与查询、稳定性与排障、AI 智能化、商业与需求、技术赛事等）。
   - **结论与指标先行**：剔除“正在排查”、“尝试了某种方法”等过程性流水账，突出根本原因、已解决措施与关键定量指标（如“修复 5+ 处”、“内存溢出配置 Swap 根治”、“进度 60% -> 100%”）。
   - **闭环下周计划**：基于本周未决问题、当前迭代阻塞点或下一阶段里程碑，自动推导可落地的下周行动项（拒绝假大空泛泛而谈）。
2. **第二层：📈 项目精简进度汇报 (Executive Traffic-Light Pulse)**
   - **项目名称与状态灯**：🟢 正常/关键突破/已上线 | 🟡 推进中/迭代中/方案确认 | 🔴 风险/阻塞/故障排查。
   - **一句话价值提炼**：高度凝练本周从什么阶段跨越到什么阶段、交付了什么核心业务/技术价值。
3. **第三层：🔄 增量动态合并与补丁协议 (Incremental Patching)**
   - 支持随时吸纳后续用户提交的“补充：...”，在不破坏原有结构的前提下智能升级状态（如将“调试中”更新为“打通并优化 RAG 参数”）并重新平衡大盘。
4. **第四层：🔗 真值与超链零损保持 (Ground Truth & Link Integrity)**
   - 严格保留所有在线 Demo 链接、飞书文档/纪要链接、GitHub 仓库地址、凭证密码和审计 ID，严禁篡改、截断或臆造。

## 强制纪律 (Trace Discipline)

首次接管或执行提炼时，必须输出一次：
`[Trace: Guyue/WorkPulseDistiller] 归集多源日报碎片，去噪提炼双层交付：结构化周报与项目红绿灯进度看板`

只有新增补充日志、调整项目状态判定或输出结构发生变更时，才追加 Trace 日志。

## 适用路由边界 (Route Boundary)

### 正向触发 (When to Use)
- 用户输入 `生成周报 + 记录`、`生成周报` 伴随任何单天/多天工作记录或零散日志。
- 用户提供多条、多天或零散日报，要求“整理周报”、“生成周报”、“梳理每周工作”、“工作记录生成周报”。
- 用户要求输出“项目精简进度”、“各项目周进度”、“项目进度看板”。
- 用户在周报生成后追加“补充：...”，要求更新周报和进度。
- 需要将复杂的研发/运维/商务碎片整合为同时满足**研发协作**与**管理层汇报**的标准文档。

### 负向排除 (Do Not Use)
- 仅需要撰写单一系统的技术架构设计方案（使用 `system-design`）。
- 仅需要对已验证的代码/功能沉淀团队教程或标准作业流程（使用 `sop-maker`）。
- 仅需要润色一段单独的文本或通告让其更通俗（使用 `human-voice`）。
- 仅需要排查线上 500 报错或抓取实时错误栈（使用 `debugging-mindset`）。

## 稳定输入协议 (Input Protocol)

蒸馏器支持以下多源异构输入格式：

| 输入类型 | 典型特征 | 提取要求 |
| :--- | :--- | :--- |
| **极速组合触发** | 包含 `生成周报 + 记录` 或 `生成周报：\n...` | 立即激活蒸馏器，解析附带记录，直接交付标准双层报告与看板 |
| **按天日报流** | 连续多天的打卡日报，同一项目可能出现在不同天 | 按项目实体聚合，合并同类项，计算累计修复项 |
| **混合项目流** | 单条消息内混杂研发、商务沟通、赛事调研、运维排障 | 识别项目别名（如 VideoStudio / FlowOps / 站点审计），分流归类 |
| **超链与物料** | 含有 Cloud Run 链接、GitHub 仓库、飞书智能纪要、密码凭证 | 100% 提取并保留为可点击超链接，注明用途 |
| **增量打补丁** | 带有“补充：”、“还有一项...”等晚到信息 | 定位目标项目节点，升级进展状态，重新计算总结 |

## 提炼与重构引擎 (Distillation Engine)

```
[原始零散碎片] ──> (1. 实体识别与归流) ──> (2. 脱水去噪与指标提炼)
                      │                               │
                      ▼                               ▼
               [项目实体池]                   [定性结论/定量数据/外链]
                      │                               │
                      └───────────────┬───────────────┘
                                      │
                         (3. 双层金字塔生成)
                                      ├──> 📊 本周工作周报 (进展细分 + 下周闭环)
                                      └──> 📈 项目精简进度汇报 (红绿灯 + 一句话价值)
```

### 步骤 1：实体归类与别名消歧
- 建立项目实体字典：
  - *AI 视频平台* = VideoStudio = AI 视频平台 Demo = 视频创作平台
  - *工单流转系统* = FlowOps = 工单系统迭代 = 自动化工单平台
  - *站点审计系统* = SiteAuditor = 网站合规诊断 = 站点质量审计
  - *开发门户* = AgentPortal = 开发门户平台 Hub = 智能体中心
  - *商务/客户交付* = 商业客户定制 AI 办公 Agent = 客户定制需求
  - *赛事/技术创新* = 云计算亚太区 AI 黑客松 = 黑客松比赛
  - *自动化工具* = 自动化云资源管理项目 = 云运维脚本

### 步骤 2：过程脱水与结论沉淀
- **过滤**：删除“正在排查...”、“协助排查...”、“暂定范围...”等过渡态描述。
- **转化**：
  - 过程：“龙虾所在机器流量异常，排查中...” ➔ **结论**：“确认并定位流量异常原因为子网关 Key 失效引发的重试风暴，已通过暂停任务止损。”
  - 过程：“VM 卡死排查和修复” ➔ **结论**：“排查并根治 VM 虚拟机因内存溢出导致的卡死故障，通过限制容器内存上限及新增 Swap 分区完成高可用加固。”
  - 过程：“开发剪辑功能，进度 90%... 剪辑功能开发完成” ➔ **合并结论**：“剪辑模块全流程闭环，支持视频裁剪、倍速、字幕添加与多格式导出。”

### 步骤 3：红绿灯状态判定矩阵 (Traffic-Light Heuristics)

| 状态标识 | 适用场景 | 判定标准 |
| :--- | :--- | :--- |
| 🟢 **正常 / 关键突破 / 已上线 / 架构迁移** | 里程碑达成、版本发布、架构迁移平稳落地、主要功能闭环、故障彻底根治 | 本周核心目标按期完成，无重大未决阻断 |
| 🟡 **推进中 / 迭代中 / 方案确认 / 高层决策** | 处于方案设计、多轮商务/需求对齐中、处于测试阶段、跨团队沟通中 | 进展受控，但需要下一步外部决策、测试验收或后续代码实现 |
| 🔴 **风险 / 阻塞 / 故障排查中** | 外部拦截导致功能不可用、出现未解系统级故障、严重延期、依赖阻塞 | 存在明显技术瓶颈或外部不可抗力，需要重点关注与资源倾斜 |

## 两层输出契约 (Output Contract)

输出必须遵循以下标准结构：

```markdown
### 📊 本周工作周报

#### 1. [项目名称]
* **本周进展：**
  * **[维度分类 1]**：[具体结论，加粗关键成果与数据]，如修复 **5+** 项异常。
  * **[维度分类 2]**：[具体结论，保留有效链接与凭证]：[链接文本](https://example.com/demo)。
* **下周计划：**
  * [基于本周遗留或下一阶段里程碑推导的明确行动项 1]。
  * [明确行动项 2]。

---

### 📈 项目精简进度汇报 (本周)

* **[项目名称 1]**
  * **进度**：[🟢/🟡/🔴] **[主状态 / 一级关键词]**
  * **总结**：[1~2句话，涵盖阶段跨越、攻克难点与核心业务/工程价值]。
```

## 增量补充协议 (Incremental Patching Protocol)

当用户在生成周报后发出增量补充（例如“补充：FlowOps 飞书机器人问答已打通，并优化了查询”）：

1. **增量解析**：识别补充内容归属的目标项目。
2. **状态晋级**：将原周报中的“调试中/排查中”原地晋级为“已打通/已上线/已重构”，补充关键参数（如“RAG 参数调优”、“索引重构”）。
3. **周计划与进度重算**：若补充内容已提前完成原定下周计划，自动刷新下周计划为更进阶的任务，并同步刷新该项目的进度灯与一句话总结。
4. **全量刷新输出**：重新输出整洁完整的最新版周报与进度汇报，确保用户可直接一键复制交付。

## 否定清单 (Anti-Patterns)

- ❌ **严禁保留无结论的过程流水账**：严禁把“试了几次没成功”、“周二在开会”、“排查中”直接搬进周报。
- ❌ **严禁丢失或臆造超链接与凭证**：所有原始日报中的飞书文档链接、GitHub 地址、云托管部署地址、密码凭证必须完整无误保留。
- ❌ **严禁下周计划脱离事实假大空**：下周计划必须紧扣本周的技术缺陷修复、下一里程碑（如测试转上线、商务转立项、设计转原型）。
- ❌ **严禁缺少项目精简进度看板**：周报必须同时交付【详细周报】与【红绿灯精简看板】，缺一不可。
- ❌ **严禁多日碎片简单复制粘贴**：同一项目本周多次出现的日志必须融合为一条条有逻辑层次的进展，禁止出现 5 个日期的项目流水账堆叠。

## 经典实战案例参考 (Real-World Case Reference)

### 案例 1：多项目研发与架构演进
- **输入特征**：包含云托管迁移、飞书 RAG 机器人、站点审计 5 项改进、AI 视频平台 UI 重构。
- **输出成果**：
  - FlowOps 提炼出“云托管容器化迁移（解决 5+ 部署问题）”与“飞书机器人问答与 RAG 调优”。
  - SiteAuditor 提炼出“稳定性兜底”与“5 项深度用户反馈方案设计”。
  - 状态精准标记为：FlowOps (🟢 架构升级与智能化落地)、VideoStudio (🟢 体验全面升级)、SiteAuditor (🟡 方案确认转入开发)。

### 案例 2：商业化、赛事与运维排障
- **输入特征**：商业定制 10 万预算商务谈判、亚太区 AI 黑客松设计说明书、FlowOps VM OOM 排查、云资源自动建项目工具。
- **输出成果**：
  - 自动划分为“业务拓展”、“技术赛事”、“核心业务平台”、“基础设施与工具”四大清晰业务线。
  - 商业定制项目准确标注状态为 🟡 推进中 / 方案报价与高层决策。
  - 黑客松项目准确标注状态为 🟢 正常 / 参赛方案设计闭环。
